# DOC-DEV-019 个人账号注册与团队邀请

2026-11-19 · RAW-030 / REQ-057 / DES-047 / DEV-041 / TST-068 / REL-014

## 需求

用户可公开注册个人账号，使用邮箱和密码登录。注册无需团队名称。登录后，通过邀请码或邀请链接加入部署中的团队。受邀成员加入前，团队项目、资产、模型配置及成员信息由后端拒绝访问。

## 设计和实现

DES-047 / DEV-041。账号增加 team_member 字段。新注册账号 active=true、team_member=false，普通账号以 viewer 角色进入待加入页面。首个注册账号取得平台初始化权限，登录后可以创建此部署的团队。当前沿用单团队部署，团队创建入口在已有团队时关闭。

已有注册账号由管理员按邮箱邀请。邀请本身不会改变其权限。接受时检查账号与邀请对应关系、有效期和一次性状态，在同一事务内更新团队角色和消费邀请。密码沿用注册时设置的值。管理员仍可邀请新邮箱，受邀人通过原激活页面设置密码。

旧账号通过迁移 004 自动保留团队身份。已有团队和业务资源继续沿用。兼容旧客户端的 setup 接口保留，现有前端统一展示普通登录和注册。

新增接口 POST /api/register、POST /api/team、POST /api/team/join 和 GET /api/invitations/{token_value}，已写入 OpenAPI。 [接口规范](../../backend/openapi.json)

## 手动验收 TST-068

1. 在登录页点击注册，填写姓名、邮箱和密码，确认表单没有团队字段。
2. 首次部署的第一位注册者登录后可以创建团队。后续注册者进入加入团队页面。
3. 未受邀账号直接请求项目、资产和模型列表，确认接口返回 403。
4. 管理员按已注册邮箱邀请，受邀人粘贴邀请码或打开链接接受，确认进入工作台。
5. 退出后使用注册时的密码登录。重复使用已接受的邀请应提示邀请无效。
6. 用原有管理员账号检查项目、工作流、模型和团队成员。

未加入团队的账号当前显示加入团队入口，创作资源在接受邀请后开放。个人独立创作空间与多个团队切换属于后续扩展。
