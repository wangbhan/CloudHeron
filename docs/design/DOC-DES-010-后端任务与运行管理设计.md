## DES-027 持久任务调度与重复提交

`jobs` 表作为队列来源，按 created_at、rowid 领取 queued 任务，原子更新为 running。并发默认 2，范围 1–8；每用户 pending 默认 10，范围 1–100。启动时 queued 保留，running 标记失败并记录可见错误；已完成节点保持，执行中节点标记失败。对话同步追加一次失败消息。重新启动服务不是一次新的用户运行指令，不重试曾执行的任务。

`request_keys` 独立表保存 owner_id、scope、key_hash、request_hash、job_id 和 created_at。Idempotency-Key 为 1–128 位字母、数字、点、下划线、冒号或连字符；按账号及入口隔离。JSON 键排序后计算请求指纹。相同键、相同请求返回原任务和 `Idempotency-Replayed: true`；相同键、不同请求返回 409。权限先验证，命中后跳过任务上限、当前配置变化与生成过程；新记录和任务、对话输入在同一事务写入。失败任务也只返回原失败记录，新的执行必须使用新键。无键请求沿用现有行为。

## DES-028 运行配置、健康检查与正常停机

数据目录 `.runtime.lock` 先于数据库初始化创建，存放 PID 与随机标识，防止同一目录两个执行器。存活 PID 拒绝第二实例；进程已退出时回收旧锁；格式损坏时报告人工检查。退出时仅释放本实例的锁。锁和本机数据忽略 Git。

`GET /api/health` 与 `/api/ready` 无需登录，只返回运行状态和版本，不披露团队或凭据。ready 以数据库可查询、服务未停机为准，停机返回 503。`GET /api/system/status` 仅管理员可看队列总数、工作线程配置和服务状态。

SIGTERM/SIGINT 或程序调用 close 时停止领取 queued，停止接收新请求，等已领取任务与当前 HTTP 请求完成后再关闭 SQLite、释放目录锁。剩余 queued 保留，下一次 listening 后再调度。重复 close 返回同一 Promise。部署脚本提供显式 Node/数据目录/端口配置与健康探测，面向单机进程托管；本轮只更新本机，正式生产发布另行记录。
